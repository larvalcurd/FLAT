# 1. Введение

## 1.1. Название

MicroPascal — учебный императивный язык программирования в стиле Pascal.

## 1.2. Назначение

MicroPascal разрабатывается как объект реализации учебного компилятора. Язык имеет компактный и формализованный набор конструкций, достаточный для демонстрации основных этапов компиляции: лексического, синтаксического и семантического анализа, а также генерации исполняемого кода.

Основные особенности языка:

- строгая статическая типизация;
- отсутствие неявного преобразования типов;
- явное объявление переменных и констант;
- базовые типы `integer`, `boolean` и `string`;
- блочная структура программ;
- условные конструкции и циклы;
- ввод и вывод;
- массивы и записи;
- процедуры и функции;
- отсутствие явного управления памятью;
- регистронезависимость исходного кода.

Язык ориентирован на минимальный, но законченный набор возможностей, достаточный для реализации компилятора в рамках учебного курса.


## 1.3. Связь с Pascal

Основным языком-ориентиром для MicroPascal является **Free Pascal**, как современный диалект Pascal, сохраняющий классическую структуру языка и расширяющий её дополнительными возможностями.

Если поведение языка явно не определено данной спецификацией, оно ориентируется на принципы и синтаксические решения Free Pascal.

При прямом противоречии между данной спецификацией и Free Pascal приоритет имеет спецификация MicroPascal.

Набор конструкций MicroPascal **полностью определяется настоящей спецификацией**. Free Pascal используется исключительно как ориентир для поведения конструкций, уже включённых в язык, но не является источником дополнительных возможностей. Любая конструкция Free Pascal, **не описанная в настоящей спецификации** (например, `case`, `repeat..until`, `goto`, `with`, множества, модули, вариантные записи, файловые типы), в MicroPascal **отсутствует**.

## 1.4. Отличия от Free Pascal

MicroPascal сознательно ограничивает и изменяет ряд возможностей Free Pascal.

В частности:

- точка с запятой `;` используется как **терминатор инструкции**, а не как разделитель;
- набор ключевых слов ограничен конструкциями, необходимыми для первой версии языка;
- `type`, `for`, `to` и `downto` не входят в первую версию языка;
- `integer`, `boolean`, `string`, `true`, `false`, `write`, `writeln`, `read` и `readln` являются зарезервированными ключевыми словами;
- поддерживается только ASCII-набор букв для идентификаторов.

При этом разрешение символа `_` в идентификаторах и поддержка комментариев `//` и `{ ... }` соответствуют используемому диалекту Free Pascal.

# 2. Лексика

Лексика MicroPascal определяет правила образования лексем исходного текста.

К основным категориям лексем относятся:

- идентификаторы;
- ключевые слова;
- числовые литералы;
- булевы литералы;
- строковые литералы;
- операторы;
- разделители и специальные символы;
- комментарии.

Лексический анализ выполняется слева направо. При наличии нескольких подходящих лексем выбирается максимально длинная лексема.


## 2.1. Набор допустимых символов

Исходный текст MicroPascal может содержать:

- латинские буквы `A–Z` и `a–z`, а также символ `_`, который для целей образования идентификаторов рассматривается как буква (см. 2.2);
- цифры `0–9`;
- специальные символы: `: = < > + - * / ; , . ( ) [ ] { } '`;
- пробельные символы (см. 2.11);
- символы внутри строковых литералов (см. 2.6);
- символы внутри комментариев (см. 2.10).

Символ `/` не образует самостоятельной лексемы:  единственный контекст вне строковых литералов и комментариев, в котором он допустим, — начало последовательности `//` (см. 2.10.1). Использование `/` вне этой последовательности является лексической ошибкой.

Символ `}` также не образует самостоятельной лексемы: единственный контекст, в котором он допустим, — закрытие блочного комментария вида `{ ... }` (см. 2.10). Использование символа `}` вне контекста завершения комментария является лексической ошибкой.

Символы, не относящиеся ни к одной из перечисленных категорий, являются недопустимыми вне строковых литералов и комментариев.

**Примечание:** Ограничение на использование исключительно ASCII-символов относится к идентификаторам, ключевым словам, операторам и числовым литералам. Содержимое строковых литералов (см. 2.6) и комментариев (см. 2.10.3) может легально включать байты расширенного диапазона `0x80–0xFF`.

## 2.2. Идентификаторы

Идентификатор используется для обозначения переменных, процедур, функций, типов и других именуемых сущностей.

Формат идентификатора:

```
identifier ::= letter { letter | digit }
letter ::= A..Z | a..z | _
digit ::= 0..9
```

Идентификатор должен начинаться с латинской буквы или символа `_`. После первого символа могут использоваться латинские буквы, цифры и `_`.

Корректные идентификаторы:

```
x
number
student1
totalSum
average
_user
total_sum
```

Некорректные идентификаторы:

```
2value
student-name
```

Символ `_` допускается в любой позиции идентификатора.

### 2.2.1. Регистронезависимость

MicroPascal является регистронезависимым языком.

Следующие записи считаются одним и тем же идентификатором:

```
Value
value
VALUE
vAlUe
```

При обработке исходного текста регистр букв не влияет на идентификацию имени.

### 2.2.2. Длина идентификатора

Максимальная длина идентификатора спецификацией не ограничивается. Практический предел может определяться реализацией компилятора (аналогично ограничению длины строкового литерала, см. 2.6.3).

### 2.2.3. Зарезервированные слова

Идентификатор не может совпадать с ключевым словом MicroPascal независимо от регистра.

Например, имена:

```
program
Program
PROGRAM
```

не могут использоваться как идентификаторы.

## 2.3. Ключевые слова

Ключевые слова являются зарезервированными словами языка и распознаются лексическим анализатором отдельно от идентификаторов.

В первой версии MicroPascal используются следующие ключевые слова:

```
program
var
const
procedure
function
integer
boolean
string
record
array
of
begin
end
if
then
else
while
do
write
writeln
read
readln
true
false
and
or
not
div
mod
```

Ключевые слова регистронезависимы.

Например:

```
PROGRAM
Program
program
```

распознаются как одно и то же ключевое слово.

Слова `and`, `or`, `not`, `div` и `mod` являются буквенными операторами и одновременно относятся к ключевым словам языка.

`true` и `false` являются булевыми литералами и также зарезервированы как ключевые слова.


## 2.4. Целые литералы

Целый литерал представляет десятичное целое число.

Формат:

```
integer-literal ::= digit { digit }
```

Знак `+` или `-` не входит в состав литерала.

Корректные литералы:

```
0
1
42
1000
2147483647
```

Целые литералы не могут содержать ведущие нули, кроме самого литерала `0`.

Корректно:

```
0
7
42
```

Некорректно:

```
007
00042
```

Отрицательное число не образует отдельную лексему. Например:

```
-5
```

состоит из двух лексем:

```
-
5
```

Проверка допустимого диапазона значений целочисленного литерала, а также обработка граничных случаев (в частности, записи `-2147483648`) относятся к семантическому анализу и не входят в настоящий раздел.

## 2.5. Булевы литералы

Булевый тип имеет два литерала:

```
true
false
```

`true` представляет истинное значение, `false` — ложное.

Булевы литералы регистронезависимы:

```
true
TRUE
True
```

обозначают одно и то же значение.


## 2.6. Строковые литералы

Строковый литерал заключается в одинарные кавычки `'`.

Формат:

```
string-literal ::= "'" { string-character } "'"
```

Корректные строковые литералы:

```
'hello'
'MicroPascal'
'Hello, world!'
''
```

Пустая строка допускается.

Внутри строкового литерала допустимы печатные символы, включая пробел (SP), а также байты расширенного диапазона (`0x80–0xFF`), которые трактуются как байты содержимого без интерпретации, **кроме**:

- одиночного символа `'` (апострофа), не входящего в удвоенную пару (см. 2.6.1) — он завершает литерал;
- символов конца строки `LF` (`0x0A`) и `CR` (`0x0D`) (см. 2.11) — они делают литерал незакрытым (см. 2.6.2).

Управляющие символы (коды `0x00–0x08`, `0x0B`, `0x0C`, `0x0E–0x1F`, `0x7F`), за исключением горизонтальной табуляции (`HT`, `0x09`), внутри строкового литерала **запрещены** и являются лексической ошибкой. Горизонтальная табуляция допускается внутри строки как обычный символ содержимого.

В частности, символы `{`, `}`, последовательность `//` и любые другие печатные символы внутри строкового литерала не имеют специального значения и рассматриваются как обычные символы содержимого строки.

### 2.6.1. Удвоенная одинарная кавычка внутри строки

Одинарная кавычка внутри строкового литерала записывается двумя последовательными одинарными кавычками (удвоенной одинарной кавычкой):

```
'John''s book'
```

Такой фрагмент представляет строку:

```
John's book
```

Различение одиночной кавычки `'` (завершающей литерал) и пары кавычек `''` (представляющей кавычку внутри строки) требует заглядывания на один символ вперёд: если непосредственно за кавычкой следует ещё одна кавычка, обе рассматриваются как часть содержимого строки и не завершают литерал.

Другие escape-последовательности не поддерживаются.

### 2.6.2. Перенос строки

Строковый литерал не может пересекать границу строки исходного файла.

Например:

```
'Hello
world'
```

является ошибкой.

Незакрытый строковый литерал является лексической ошибкой.

### 2.6.3. Длина строкового литерала

Максимальная длина строкового литерала спецификацией не ограничивается. Практический предел может определяться реализацией компилятора.


## 2.7. Операторы

MicroPascal поддерживает следующие операторы.

**Арифметические**

```
+
-
*
div
mod
```

**Операторы сравнения**

```
=
<>
<
<=
>
>=
```

**Логические**

```
and
or
not
```

**Присваивание**

```
:=
```

Операторы `and`, `or`, `not`, `div` и `mod` являются буквенными ключевыми словами.

Оператор `:=` одновременно указан в разделе 2.8 как специальная лексема; это отражает его двойную роль — оператора присваивания и элемента синтаксической структуры программы, аналогично буквенным операторам, являющимся одновременно ключевыми словами.

Оператор `/` в MicroPascal отсутствует как самостоятельная лексема (см. также 2.1).


## 2.8. Разделители и специальные символы

В языке используются следующие однозначные и составные специальные лексемы:

| Лексема | Назначение |
|---|---|
| `(` | открывающая круглая скобка |
| `)` | закрывающая круглая скобка |
| `[` | открывающая квадратная скобка |
| `]` | закрывающая квадратная скобка |
| `,` | разделитель элементов списка |
| `:` | обозначение типа |
| `;` | терминатор инструкции |
| `.` | точка |
| `..` | диапазон массива |
| `:=` | присваивание |

Точка `.` и последовательность `..` распознаются как разные лексемы.

`:=` также указан в разделе 2.7 в списке операторов (см. пояснение о двойной роли там же).

## 2.9. Точка с запятой

Символ `;` является терминатором инструкции.

Инструкция завершается точкой с запятой, в том числе последняя инструкция перед `end`.

Использование `;` как терминатора является сознательным отличием MicroPascal от Free Pascal, в котором точка с запятой используется как разделитель.

## 2.10. Комментарии

MicroPascal поддерживает два вида комментариев:

```
// однострочный комментарий
```

и

```
{
 многострочный комментарий
}
```

### 2.10.1. Однострочные комментарии

Комментарий начинается последовательностью `//` и продолжается до конца строки.

Пример:

```
x := 10; // присваивание
```

Текст однострочного комментария не образует лексем.

### 2.10.2. Многострочные комментарии

Многострочный комментарий начинается символом `{` и завершается первым символом `}`.

Пример:

```
{
 это комментарий
 в несколько строк
}
```

Вложенные комментарии не поддерживаются.

Например, в конструкции:

```
{
 first { second } third
}
```

первый символ `}` завершает комментарий.

Незакрытый комментарий до конца исходного файла является лексической ошибкой.


### 2.10.3. Содержимое комментариев
Внутри комментариев обоих видов разрешены любые печатные ASCII-символы (коды `0x20–0x7E`), байты расширенного диапазона (`0x80–0xFF`), а также символы перевода строки (`LF`, `0x0A`), возврата каретки (`CR`, `0x0D`) и горизонтальной табуляции (`HT`, `0x09`).

Управляющие символы (коды `0x00–0x08`, `0x0B`, `0x0C`, `0x0E–0x1F`, `0x7F`), включая нулевой символ `NUL` (`0x00`), внутри комментариев **запрещены** и вызывают лексическую ошибку.

Внутри текста комментария символы `'`, `{`, а также последовательность `//` не имеют своего обычного лексического значения и рассматриваются как обычные символы содержимого.

Символ `}` внутри однострочного комментария `//` также не имеет специального значения. Внутри многострочного комментария `{ ... }` первый же встреченный символ `}` завершает комментарий (см. 2.10.2).


## 2.11. Пробельные символы

К пробельным символам относятся:

| Обозначение | Код | Назначение |
|---|---|---|
| SP | `0x20` | пробел |
| HT | `0x09` | горизонтальная табуляция |
| LF | `0x0A` | перевод строки |
| CR | `0x0D` | возврат каретки |
| FF | `0x0C` | формулярный перевод |

Пробельные символы не образуют самостоятельных токенов и игнорируются лексическим анализатором, кроме их влияния на границы строк и диагностические позиции.

Последовательность CRLF рассматривается как один перевод строки при подсчёте номеров строк.


## 2.12. Лексические ошибки

Лексическая ошибка возникает, если последовательность символов не соответствует ни одной допустимой лексеме.


К лексическим ошибкам относятся:

-   недопустимый символ или байт вне строкового литерала или комментария (см. 2.1);
-   символ `/`, не входящий в состав последовательности `//` (см. 2.1);
-   символ `}`, не являющийся терминатором многострочного комментария (см. 2.1);
-   некорректный формат целочисленного литерала: наличие ведущих нулей, кроме литерала `0` (см. 2.4);
-   недопустимый управляющий байт внутри строкового литерала (см. 2.6);
-   недопустимый управляющий байт внутри комментария любого вида (см. 2.10.3);
-   незакрытый строковый литерал (достижение конца строки `CR`/`LF` или конца файла `EOF` до закрывающей кавычки) (см. 2.6.2);
-   незакрытый многострочный комментарий (достижение конца файла `EOF` до терминатора `}`) (см. 2.10.2).

При обнаружении лексической ошибки компилятор должен сообщить об ошибке с указанием позиции в исходном тексте.
